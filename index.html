REVERSIBILITY

Throwing away the activations

A 19.96M-parameter transformer trained four times on 50M tokens of TinyStories, on a 16 GB M1 Pro. The question: can you throw away the stored activations and rebuild them during the backward pass, and what does it cost?

The answer, in one table

All four runs, 50,003,968 tokens each, same seed, same data order
RunVariantBatchSteps Final lossTokens/sPeak GB
01baseline86,1041.768612,4965.57
02euler86,1041.749212,7265.57
03midpoint_rev86,1041.768210,2313.82
04midpoint_rev321,5262.08709,4889.32

Three findings

1. Reversibility is free in loss terms

Run 03 finished 0.022% from the baseline while using 51.7% less memory. It costs 1.22× per step — the extra forward evaluation the reconstruction needs.

2. Euler trains best and cannot be reversed

It beat the baseline by 1.10% on loss while being 65% wrong on reconstruction. Reconstruction quality and optimisation quality turn out to be independent properties.

3. The bigger batch is better per step and worse per token

At step 1,526 run 04 was 0.18 ahead of run 03. At 50M tokens it was 0.32 behind. Same model, same data — the difference is 1,526 optimizer steps against 6,104.
